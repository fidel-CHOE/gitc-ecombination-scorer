# e-Combination 자가채점기

2026 GITC(Global IT Challenge for Youth with Disabilities) **e-Combination** 종목 제출물을
채점 루브릭 그대로 100점 만점으로 채점하고, 어디를 더 채워야 점수가 오르는지 알려주는 도구입니다.

**👉 [바로 쓰기](https://GITHUB_OWNER.github.io/gitc-ecombination-scorer/)**

파일은 브라우저 안에서만 열립니다. 서버로 전송되지 않고, 어디에도 저장되지 않습니다.

---

## 왜 만들었나

2026년 7월 한국예선 제출물 44건을 전수 분석한 결과, 점수가 낮은 학생들의 문제는
**답을 못 써서가 아니라 완주를 못 해서**였습니다.

- 비발달 유형 발표자료 제출 13건 중 **9건이 원본 양식 그대로**(또는 파일 오제출)였습니다. 40점을 통째로 버린 것입니다.
- 엑셀 함수 6문항을 모두 맞히고 차트 6개까지 만들어 놓고 발표자료를 내지 않아 47점을 받은 학생이 있었습니다.
- 정보 검색 30점 만점을 받고도 발표자료가 백지여서 41점을 받은 학생이 있었습니다.
- 발표자료 기본 기능 5점(페이지 번호·이동 링크·대체 텍스트·서식 통일)은 **9명 중 8명이 그냥 버렸습니다.**

그래서 이 도구는 "잘 썼는지"보다 **"빠뜨린 게 있는지"를 먼저 잡아냅니다.**
제출 전에 스스로 한 번 돌려보는 것만으로 위 손실의 대부분을 막을 수 있습니다.

## 무엇을 채점하나

100점 = 정보 검색 30 + 엑셀 30 + 발표자료(또는 제출 문서) 40

| 구분 | 배점 | 채점 방식 |
|---|---|---|
| 검색의 효과성 (검색엔진 · 생성형 AI) | 10 | 내용 판정 |
| GPT 활용 기법 | 5 | **자동** — 역할 지정·예시 제시·단계별 사고·형식 지정·맥락 제시를 프롬프트에서 탐지 |
| 출처 다양성 (검색엔진 · AI) | 10 | **자동** — 서로 다른 도구 종류 수 |
| 신뢰성 · 인용 | 5 | 내용 판정 |
| 엑셀 표 구조 & 헤더 | 5 | **자동** |
| 엑셀 함수 6문항 | 12 | **자동** — 함수 존재 + 정답 여부 + 참조 범위까지 검증 |
| 자체 표 함수 적용 | 3 | **자동** |
| 표 작성 개수 · 차트 작성 개수 | 10 | **자동** |
| 발표자료 내용 (제목·목차 / 분석 / 방향성 / 메시지) | 35 | 내용 판정 |
| 발표자료 기본 기능 | 5 | **자동** — 페이지 번호·이동 링크·대체 텍스트·서식 통일 |

**자동 채점 50점은 어디서 열어도 그대로 동작합니다.**

내용 판정 50점은 글을 읽어야 점수가 나옵니다. 채점 결과 화면의 **‘AI에게 물어보기’** 버튼을 누르면
학생이 쓴 글과 채점 기준을 묶은 질문이 클립보드에 복사됩니다. Claude·ChatGPT·Gemini 등
무료로 쓸 수 있는 아무 AI 채팅창에 붙여넣으면 항목별 점수와 근거를 알려 주고,
그 답을 다시 붙여넣으면 **100점 만점 총점이 완성됩니다.** 별도 계정 연결이나 API 키가 필요 없습니다.

### 자동 채점이 잡아내는 것

단순히 "함수가 있는가"가 아니라 실제로 계산이 맞는지 봅니다. 예선 제출물에서 실제로 나온 사례:

```
K6 = IF(G5<=2%, "Select", "-")     ← 자기 행이 아니라 윗행 참조. 50칸 전부 밀림 → 0점
E59 = vlookup                       ← 함수 이름만 타이핑. 괄호가 없어 계산 안 됨 → 0점
```

엑셀이 '채우기'로 복사한 수식(공유 수식)도 각 칸 위치로 옮겨 계산해 판정합니다.

발표자료는 **원본 양식과 대조**해서 학생이 실제로 바꾼 글자만 남깁니다.
배포된 양식이 여러 판(수정 전/후)이라 대조 해시는 모든 판의 합집합으로 만들었습니다.

여기에 더해 **양식의 안내 문구가 남아 있는지**를 따로 잡아냅니다.
“…제목을 작성하세요”, “Tip : …” 같은 문장은 무엇을 쓰라는 안내이지 답이 아닙니다.
그대로 남아 있으면 채점위원은 미작성으로 봅니다. 예선 제출물로 확인한 결과:

| 학생 | 안내 문구가 남은 쪽 | 실제 |
|---|---|---|
| 백지로 제출한 학생 | 1·2·3·4쪽 전부 | 발표자료 점수 대부분 손실 |
| 끝까지 작성한 학생 | 없음 | 정상 채점 |

## 검증

실제 예선 제출물과 채점위원 채점 결과를 대조했습니다. 엑셀 함수 12점 구간:

| 학생 | 이 도구 | 채점위원 |
|---|---|---|
| A | 10 / 12 | 10 / 12 |
| B | 8 / 12 | 8 / 12 |
| C | 0 / 12 | 0 / 12 |

검증 스크립트는 `tools/verify.js` 에 있습니다. 학생 제출물은 개인정보이므로 저장소에 포함하지 않습니다.

## 쓰는 법

1. 유형을 고릅니다 — 발달 / 비발달 / 시각
2. 엑셀 파일과 발표자료(시각 유형은 워드 문서)를 끌어다 놓습니다
3. **채점하기** — 자동 채점 50점이 바로 나옵니다
4. 나머지 50점은 **‘AI에게 물어보기’** → 복사 → AI 채팅창에 붙여넣기 → 받은 답을 다시 붙여넣고 **점수 반영**

보호자·선생님이 함께 봐 주시면 좋습니다. 3·4번은 어른의 도움이 필요할 수 있습니다.

### ⚠️ 암호가 걸린 파일

대회 배포 양식에는 암호가 걸려 있고, 학생이 그대로 저장하면 제출 파일에도 남습니다.
브라우저는 암호가 걸린 파일을 열 수 없습니다. 파일을 연 뒤
`파일 → 정보 → 통합 문서 보호 → 암호 설정`에서 암호를 지우고 다른 이름으로 저장해서 넣으세요.
**대회 제출용 원본은 그대로 두시면 됩니다.**

연습·과제용으로 배포할 때는 아예 암호 없는 양식을 나눠 주는 편이 편합니다.

## 문제 세트 추가하기

함수 6문항과 발표자료 채점 항목은 문제마다 다릅니다. `src/app.html` 맨 위의 `SETS` 객체에
유형별로 분리되어 있으니, 새 문제를 낼 때 이 블록만 복사해서 고치면 됩니다.

```js
const SETS = {
  other: {
    label: "비발달 유형",
    doc: "pptx",                       // 산출물 형식 (pptx | docx)
    fx: [                              // 엑셀 함수 6문항
      { id:"f1", label:"COUNTIF — …", fn:["COUNTIF"], pts:2, answer:13,
        advice:"학생에게 보여 줄 연습 안내" },
      { id:"f4", label:"…", fn:["SUM","+"], pts:2, col:"I", from:5, to:54 },
      { id:"f6", label:"…", fn:["IF"], pts:2, col:"K", from:5, to:54, rowAlign:true },
    ],
    docItems: [                        // 발표자료 채점 항목
      { id:"d1", label:"제목 · 목차 · 소속/이름", max:5,
        rule:"채점 기준을 그대로 적습니다", advice:"연습 안내" },
    ]
  }
};
```

| 필드 | 뜻 |
|---|---|
| `fn` | 인정할 함수 이름. `"+"` 는 단순 덧셈 수식 |
| `pts` | 배점 |
| `answer` | 계산 결과의 정답. 저장된 계산값과 대조합니다 |
| `col` / `from` / `to` | 열 전체를 채워야 하는 문항. 80% 미만이면 0점 |
| `rowAlign` | 수식이 자기 행을 참조하는지 검사 (한 칸 밀림 탐지) |
| `rule` | 내용 판정에 그대로 전달되는 채점 기준 문구 |
| `advice` | 점수를 놓쳤을 때 학생에게 보여 줄 연습 안내 |

### 원본 양식이 바뀌면

학생 작성분을 골라내려면 원본 양식 문구를 알아야 합니다. 대회 문제 원문을 저장소에 싣지 않기 위해
해시(FNV-1a 32bit)만 담고 있습니다. 양식이 바뀌면 다시 뽑아서 `src/app.html` 의 `TPL` 에 붙여 넣으세요.

```bash
pip install openpyxl
# 유형마다 파일을 여러 개 줘도 됩니다 — 판이 여러 개면 전부 주세요(합집합으로 씁니다)
python3 tools/make-template-hashes.py \
  --other  빈양식/Submission1_Other.xlsx 빈양식/Submission2_Other.pptx 구판/Submission2_Other.pptx \
  --dev    빈양식/Submission1_Dev.xlsx   빈양식/Submission2_Dev.pptx \
  --visual 빈양식/Submission1_Visual.xlsx
```

## 빌드

채점 로직은 `src/app.html` 한 벌뿐입니다. GitHub Pages 배포본은 여기에 HTML 뼈대만 씌운 것입니다.

```bash
node tools/build.js      # src/app.html → docs/index.html
```

Pages 설정: Settings → Pages → Source `main` 브랜치의 `/docs` 폴더.

라이브러리는 JSZip 하나만 CDN에서 불러옵니다. 나머지는 전부 이 파일 안에 있습니다.
